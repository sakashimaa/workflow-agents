# Производительность

## Бюджеты

- стартовая публичная страница: не более 150 КБ переданных JS, 15 КБ CSS и 180 КБ всего;
- медианный TTFB локального production-сервера: не более 100 мс;
- FCP в локальном headless Chromium: не более 1 с;
- приватные данные никогда не кэшируются общим кэшем.

## Замер уровня 6

Baseline снят с тега `level-5`, результат — с текущей production-сборки. Для каждого варианта выполнено семь переходов на `/` в новых страницах headless Chromium; ниже медиана. Сервер и браузер работали на одной машине, поэтому числа нужны для сравнения версий, а не для прогноза реальной сети.

| Метрика | level-5 | level-6 | Изменение |
| --- | ---: | ---: | ---: |
| TTFB | 5 мс | 2 мс | −60% |
| FCP | 64 мс | 56 мс | −12.5% |
| Весь transfer | 281 517 Б | 100 837 Б | −64.2% |
| JS transfer | 243 806 Б | 92 755 Б | −62.0% |
| CSS transfer | 29 009 Б | 5 329 Б | −81.6% |

Главные причины изменения:

1. Nitro заранее рендерит `/` и `/faq`, поэтому первый ответ не ждёт Vue SSR. Справка и статьи используют SWR на час, а приватные маршруты явно получают `private, no-store`.
2. `compressPublicAssets` создаёт и отдаёт сжатые варианты JS/CSS. Разделение кода по маршрутам Nuxt сохраняет стартовую загрузку ниже бюджета.

## Как повторить

```bash
npm ci
npm run build
PORT=3000 node .output/server/index.mjs
```

Открыть `/` в чистом контексте Chromium и собрать Navigation/Resource/Paint entries через Performance API. Для корректного сравнения использовать одинаковые Node, Chromium, железо и семь прогонов. Размеры production-бандлов дополнительно печатает `npm run build`.

Проверка SSR, метаданных, sitemap и отсутствия hydration-ошибок автоматизирована в `tests/e2e/public-ssr.spec.ts`.
